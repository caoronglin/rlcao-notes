# 序列检索与双序列比对：Entrez / EBI / EMBOSS 可复用流程

> 整理范围：库内 [[notes/生信实验/02/生物信息学实验报告_2_曹荣麟-2024014209|生信实验二]] 实操（检索日期 2026-10-24）沉淀下来的可复用步骤。
> 适用场景：给定一个分子，检索其同源序列、核对注释、比较不同数据库的记录格式、做两条序列的动态规划比对。
> 全部命令可直接复制执行；数字为实测值，不是示例。

---

## 目标

1. 用 Entrez 锁定「哪些记录属于这个分子」，而不是「哪些记录提到过它」。
2. 区分直系同源（跨物种）与并系同源（同基因组内复制），并留下可核对的登录号与版本号。
3. 读懂 EBI 五个核心库与 NCBI 的记录格式差异。
4. 用 EMBOSS Needle/Water 做双序列比对，能解释「一致性、相似性、空位分布」三个指标分别说明什么。

## 输入数据

| 项 | 本次取值 | 说明 |
|---|---|---|
| 起始分子 | 人 EGF（`gene:EGF`，Gene ID 1950） | 也可从任意 RefSeq 记录反查 |
| 核酸参考记录 | `NM_001963.6`（6388 nt） | CDS 454–4077 |
| 蛋白参考记录 | `NP_001954.2`（1207 aa） | UniProt `P01133` / `EGF_HUMAN` |
| 对照序列 | 小鼠 Egf（`NM_010113.4` / `NP_034243.2`） | 直系同源 |
| 并系同源对照 | 人 TGFA（`NM_003236.4` / `NP_003227.1`，160 aa） | 同基因组内复制 |
| 软件 | EMBOSS 6.6.0（EBI Job Dispatcher 在线版 + 本地发行版交叉验证） | 两者结果逐项一致 |

## 步骤

### 1. Entrez 检索：先想清楚「过滤什么」

关键词检索默认是**全字段自由词匹配**，基因名出现在题目、蛋白注释或文献摘要里都算命中。本次实测：

| 检索式 | 命中 |
|---|---|
| `"human epidermal growth factor"[All Fields] AND refseq[filter]` | 62 |
| `"epidermal growth factor"[All Fields] AND "Homo sapiens"[Organism] AND refseq[filter]` | 1475 |
| `"Homo sapiens"[Organism] AND mitochondrion[filter]`（Protein） | 886,234 |
| `"Homo sapiens"[Organism] AND mitochondrion[filter] AND refseq[filter]`（Protein） | 39 |

**三条可复用结论**

1. **关键词比想象中宽**。62 条里真正编码 EGF 配体的只有 5 条，其余是 EGF 通路的受体与下游基因（ERBB2 31、EGFR 10、CDK12、GPN3、ADGRF1/ADGRE3、DLK1）。
2. **「更精确」的检索式未必召回更少**。把 "human" 从关键词挪到 `[Organism]` 过滤，结果从 62 涨到 1475——因为所有物种的 EGF 家族都进来了。
3. **过滤器的威力远大于关键词**。线粒体那题加一个 `refseq[filter]`，88 万 → 39 条。

### 2. 用 E-utilities 取数（不要在网页上逐条点）

```bash
E="email=your@email.com"   # 必填，否则被限流

# 检索（先 retmax=0 只看命中数，querytranslation 用来核对检索式被解析成什么）
curl -s -G "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi" \
  --data-urlencode "db=nuccore" \
  --data-urlencode 'term="human epidermal growth factor"[All Fields] AND refseq[filter]' \
  --data-urlencode "retmax=0" --data-urlencode "retmode=json" --data-urlencode "$E"

# 批量取摘要（登录号 + 长度 + 标题，用于离线归类统计）
curl -s -G "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esummary.fcgi" \
  --data-urlencode "db=nuccore" --data-urlencode "id=<逗号分隔的UID>" \
  --data-urlencode "retmode=json" --data-urlencode "$E"

# 取 FASTA（存盘备用）
curl -s -G "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi" \
  --data-urlencode "db=nuccore" --data-urlencode "id=<acc,acc,...>" \
  --data-urlencode "rettype=fasta" --data-urlencode "retmode=text" --data-urlencode "$E"

# 跨库链接：核酸 → 蛋白（找编码产物），蛋白 → 基因 → 文献
curl -s -G "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/elink.fcgi" \
  --data-urlencode "dbfrom=nuccore" --data-urlencode "db=protein" \
  --data-urlencode "id=NM_001963" --data-urlencode "retmode=json" --data-urlencode "$E"
```

| 端点 | 用途 | 关键参数 |
|---|---|---|
| `esearch` | 检索，返回 UID 列表 | `term`、`retmax`、`retmode` |
| `esummary` | 批量取摘要 | `id`（逗号分隔，≤200–500 个） |
| `efetch` | 取全记录 | `rettype=fasta`/`gb`/`gp`、`retmode=text` |
| `elink` | 跨库链接 | `dbfrom`、`db`、`id`、`linkname` |
| `einfo` | 库与字段元信息 | `db=nuccore` |

无 API Key 时限速 3 req/s，请求间留 0.35 s；`email` 必填。

### 3. 直系同源与并系同源：检索路径不同

| 目标 | 检索路径 | 判据 |
|---|---|---|
| 直系同源 | 换 `[Organism]`，取 variant 1 的 RefSeq mRNA + 其编码蛋白 | 跨物种 + 蛋白名/结构域一一对应 |
| 并系同源 | 同一 `[Organism]` 内取同家族其它成员 | 同基因组 + 由基因复制产生 + 长度/功能已分化 |

**不要用 `XM_`/`XP_` 自动预测记录当正式引用**——预测模型随基因组注释更新而变，人工校核的 `NM_`/`NP_` 才是稳定参照。

### 4. EBI 五个库与 NCBI 的差别

| 库 | 定位 | 记录格式要点 |
|---|---|---|
| ENA | INSDC 核酸数据的欧洲分部 | **EMBL 扁平文件**：行首两位字段码（`ID`/`AC`/`DE`/`KW`/`OS`/`FT`），`XX` 分隔；登录号与 GenBank 共用 |
| UniProtKB | 蛋白注释权威词典 | **行前缀式**（`ID`/`AC`/`DE`/`GN`/`CC`/`FT`/`DR`/`SQ`），交叉引用单独成行；Swiss-Prot 575,748 条 / TrEMBL 149,430,635 条（2026_03 版） |
| Ensembl | 全基因组注释 | 统一 `ENST`/`ENSP`/`ENSG` ID 体系 + 基因组坐标；release 116 |
| ArrayExpress（→ BioStudies） | 表达组学原始数据与设计 | 检索 `epidermal growth factor` 得 1020 条研究 |
| PDBe | 大分子三维结构 | 把 PDB 编号标在残基区间上（`DR PDB; 1NQL; X-ray; 2.80 A; B=971-1023.`） |

同一个人 EGF 的三种记录（`X04571` / `NM_001963.6` / `P01133`）体量不同：ENA 的 1987 年 cDNA 只有 4871 bp，NCBI 的全长 mRNA 有 6388 bp——**同一个分子的两代记录，比对时不能混用**。

### 5. EMBOSS 双序列比对

| 工具 | 算法 | 用途 |
|---|---|---|
| Needle | Needleman-Wunsch | 全局比对，两条序列整体同源时用 |
| Water | Smith-Waterman | 局部比对，定位保守区段/结构域 |

评分矩阵：**核酸** `EDNAFULL`（匹配 +5 / 错配 −4）与 `EDNAMAT`（增加 R/Y/N 等简并碱基评分）；**蛋白** `EBLOSUM62`。

> REST 接口收的是 EMBOSS 内部矩阵名（`EDNAFULL`/`EDNAMAT`/`EBLOSUM62`），网页表单显示的标签才是 `DNAfull`/`DNAmat`。填错会直接报 `Value for "matrix" is not valid`。

```bash
# 在线提交（EBI Job Dispatcher）
curl -s -X POST "https://www.ebi.ac.uk/Tools/services/rest/emboss_needle/run" \
  --data-urlencode "email=your@email.com" \
  --data-urlencode "stype=dna" --data-urlencode "matrix=EDNAFULL" \
  --data-urlencode "asequence=<seq1>" --data-urlencode "bsequence=<seq2>" \
  --data-urlencode "gapopen=10.0" --data-urlencode "gapextend=0.5" \
  --data-urlencode "endweight=false" --data-urlencode "format=markx10"
# → 返回 jobid；轮询 /status/<jobid>（返回纯文本 FINISHED），再取 /result/<jobid>/out

# 本地复算（与 EBI 同版本，交叉验证）
export EMBOSS_DATA=<env>/share/EMBOSS/data
needle -asequence a.fa -bsequence b.fa -datafile EDNAFULL \
       -gapopen 10.0 -gapextend 0.5 -aformat3 clustal -outfile stdout -auto
water  -asequence a.fa -bsequence b.fa -datafile EBLOSUM62 \
       -gapopen 10.0 -gapextend 0.5 -aformat3 clustal -outfile stdout -auto
```

**输出里必须自己算的三件事**（EMBOSS 只给汇总）：

1. **空位游程分布**：把连续空位切段，统计「游程个数 + 每段长度」。核酸全局比对的 2165 个空位其实是 148 个游程（130 个 ≤9 bp，1 个 1498 bp）。
2. **空位的区域归因**：把比对列映射回 CDS / 5′UTR / 3′UTR。本次 CDS 空位率仅 6.9%，3′UTR 达 72.6%。
3. **局部比对的落点**：Water 找到的区间与人 EGF 成熟肽 971–1023、TGFA 成熟肽 40–89 对上，说明局部比对自动定位到了保守结构域。

## 关键参数

| 参数 | 本次取值 | 依据 |
|---|---|---|
| gap open / extend | 10.0 / 0.5 | EMBOSS 默认，对应 EDNAFULL/EBLOSUM62 |
| end weight | false | 全局比对不惩罚末端空位 |
| 核酸矩阵 | EDNAFULL + EDNAMAT | 前者比较严格；后者用于含简并碱基的序列 |
| 蛋白矩阵 | EBLOSUM62 | EMBOSS 默认 |
| 相似性判定 | EMBOSS 汇总行 | 核酸=一致性；蛋白=BLOSUM 正分替换 |

**本次 8 组作业的实测结果**（人 EGF vs 小鼠 Egf = 直系同源；人 EGF vs 人 TGFA = 并系同源）：

| 序列对 | 类型 | 矩阵 | 长度 | Identity | Similarity | Gaps |
|---|---|---|---|---|---|---|
| 核酸 | 全局 | EDNAFULL | 6663 | 54.2% | 54.2% | 32.5% |
| 核酸 | 局部 | EDNAFULL | 5154 | **70.1%** | 70.1% | 12.7% |
| 蛋白 | 全局 | EBLOSUM62 | 1231 | 65.4% | 77.7% | 3.1% |
| 蛋白 | 局部 | EBLOSUM62 | 1217 | 66.1% | 78.5% | 2.0% |
| 蛋白（并系同源） | 全局 | EBLOSUM62 | 1224 | 3.9% | 6.4% | 88.3% |
| 蛋白（并系同源） | 局部 | EBLOSUM62 | 99 | **33.3%** | 50.5% | 13.1% |

## 结果

- 全局 vs 局部：核酸全局 54.2% 被不保守的 3′UTR 稀释，局部 70.1% 才是可比数字。
- 直系同源 vs 并系同源：直系同源相似性（77.7%）远高于一致性（65.4%），说明大量替换是保守替换；并系同源即使找到共同结构域，一致性也只有 33.3%。
- DNAfull 与 DNAmat 结果**完全一致**——两条 RefSeq 序列不含任何非 A/C/G/T 碱基，两个矩阵退化成同一张打分表。

## 踩坑记录

1. **登录号会被回收复用**。按旧文献记的 `NP_005623` 现在是 **calpain-15**；`NM_003001` 现在是 **SDHC**（TGF-α 的 mRNA 换成了 `NM_003236`）。NCBI 把被抑制的旧号回收给别人了。**只记 accession 不记 version 和 title 是危险的**。
2. **ESummary 的 `version` 字段常为空**，要拿准确版本号得用 `efetch`（FASTA 头里带 `NM_001963.6`）或 `accessionversion`。
3. **EBI 主站会限流**：`www.ebi.ac.uk` 对某些 IP 返回 `temporarily blocked from submitting new sequence analysis jobs`（JDispatcher 公平使用策略）。可改用同一套服务的开发镜像 `wwwdev.ebi.ac.uk`；本地装同版本 EMBOSS 复算做交叉验证更稳。
4. **E-utilities 提交长序列用 GET 会 414**，长序列必须 POST 或改走 `efetch`。
5. **矩阵名要填 EMBOSS 内部名**（`EDNAFULL`），不是网页标签（`DNAfull`）。
6. **EBI 记录与 NCBI 记录不是同一代**，长度可差 1.5 kb（UTR 补齐），直接混用会凭空多出一大段空位。
7. **「空位数量」单独看没有意义**，必须按游程 + 区域拆开，否则会把「一个 1498 bp 的大缺口」和「148 个散布的小插入缺失」混为一谈。
