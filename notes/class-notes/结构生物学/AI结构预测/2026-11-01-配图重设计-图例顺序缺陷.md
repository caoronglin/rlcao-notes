# 综述配图重设计：修复图 1 图例顺序缺陷

## Goal

用户报告「这个图有问题」（图 1，32 篇文献的年度×主题堆叠柱状图）。目标：客观定位缺陷并修复，不让猜测替代证据。

## Findings

先做数据与像素两级核查，把「可能的问题」缩到可证伪的几条：

| 检查项 | 方法 | 结果 |
| --- | --- | --- |
| 每格篇数 | 从 `output/dataset.json` 重算年度×模块计数 | 与 FIG1 完全一致，合计 32 |
| 分段顺序 | 逐柱按精确调色板匹配像素，取长连续同色段 | 7 柱全部为 M1→M6 自下而上 |
| 配色一致性 | 统计全图不透明颜色，比对 token 调色板 | 图例色块与柱体段色一致 |
| 裁切 / 遮挡 | 扫描图顶与柱间空隙的 alpha | 无裁切；图例文字右缘距 2024 柱左缘约 3 px |

**真实缺陷只有一条，但是硬伤：图例读数顺序与堆叠顺序不一致。**

matplotlib 的 `legend(ncol=3)` 按**列**填充（先竖后横），6 个系列的视觉排布是：

```
M1 范式起点    M3 复合物与多模态    M5 序列即结构
M2 基础设施    M4 预测到设计        M6 边界与闭环
```

而柱体是 M1 在底部、M6 在顶部。读者拿着图例去对应柱体会逐个错位。附带一个小问题：图例第三列的文字右缘几乎贴上全图最高的 2024 柱，间距约 3 px。

## Changes

**`work/gen_figure.py`**

- 新增 `_reading_order(handles, labels, ncol)`：按期望的阅读顺序（左→右、上→下）反推列填充下的存放位，返回重排后的 `(handles, labels)`。handle 与 label 必须一起重排，只重排 handle 会出现「文字是 M2、色块是 M4」的错配（第一版就踩了这个坑，已由像素核查抓出）。
- `_legend()` 增加 `handles/labels` 与 `legend_bbox` 参数，支持把图例放到坐标区外。
- `draw_stacked_bar()` 改为从 `get_legend_handles_labels()` 取堆叠顺序后过一遍 `_reading_order()`。其他图型（bar/hbar/line/dual_axis）走原路径，未受影响。

**`work/make_figures.py`** — FIG1 图例从坐标区内的 `upper left` 移到坐标区下方（`bbox_to_anchor=(0.5,-0.17)`，ncol=3），`figsize` 由 `6.3,3.1` 调到 `6.3,3.45` 给图例让位。坐标区内不再有图例压柱的问题。

## Problems

**第一版修复引入了新错配。** 只重排 handle 不重排 label，导致图例第二行第一个色块变成绿色却写着「M2 基础设施」。是渲染后逐像素核对图例区抓出来的，不是看出来的。教训：改渲染管线后必须重新做像素级核查，不能只跑 audit 的结构检查（宽度/透明/字形那三项对这类错配全盲）。

## Verification

像素级复核（脚本见本次会话记录）：

- 柱体数 7，每柱分段顺序与 `dataset.json` 计数逐项一致（2020=1、2021=3、2022=2、2023=6、2024=8、2025=8、2026=4，合计 32）。
- 图例 6 个色块按 x 排序为 M1→M6，`y≈1412` 行是 M1/M2/M3，`y≈1488` 行是 M4/M5/M6，色块与系列配色一一对应。
- `audit.json`：`all_width_3000` / `all_transparent` / `all_text_as_path` 全为 true；glyph 探针 0 缺失。
- 抽查未改动的图 6，图例与柱体未回归。
- Word 重新生成，内嵌图片 6 张，1.25 MB。

## Result

图 1 图例现按 M1→M6 阅读，与堆叠顺序一致；图例移出坐标区，不再贴近最高柱。综述正文与图注文字无需改动（描述的是数据与图形含义，未涉及图例位置）。Markdown 走图片相对路径，重出 PNG 即自动生效；Word 需重跑 `md2docx.py`。
