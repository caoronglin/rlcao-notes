# 三代测序文献库可视化站点（antd CLI + React 19）

## Goal

1. 给已合并的 1709 条文献库做交互可视化站点，不能只是静态图。
2. 用 `@ant-design/cli` 查组件 API 后写代码，不靠记忆猜 antd 6 的 props。
3. 数据与 literature.xlsx / trend_report.pptx 同源，不新增、不改口径。

## Findings

- **antd CLI 是知识工具不是脚手架**：`antd` 在本机由 mise 管理（v6.6.5），不生成项目模板，只做 `info` / `doc` / `demo` / `token` / `lint` / `doctor` / `usage` 查询与体检。站点仍须自建 Vite + React 工程。
- **antd 5 → 6 的迁移坑**：`StackedColumn` 已合并为 `Column` + `stack` prop；icons v6 有组件改名（`AreaOutlined` → `AreaChartOutlined`）；Tag 的 `bordered` → `variant`；Button 的 `type` → `color`/`variant`。按 CLI 的 migrate 清单逐条核对后一次改对。
- **`研究性质` 的融合判定顺序不能反**：`未做关联融合` 四字里也含「融合」。若先判 `融合` 会把 323 篇误判成真融合；必须先排除 `多技术/多层/未做关联融合`，再判 `融合`。该逻辑在统计脚本与前端筛选里各有一份，改口径要同步。
- **gimlet 的排除记录表是二维数组**（表头行 + 数据行），不是对象数组，前端 Table 直接渲染会得到空表。`prepare_data.py` 里补一层 `dict(zip(hdr, row))` 转换。
- **Vite 端口不保证**：`--port 5199` 被占用时会静默改用 5200，`/data/literature.json` 的 404 是端口问题不是数据问题。

## Reproduction

```bash
cd ~/桌面/sandaicexu/web
python3 scripts/prepare_data.py     # 生成 public/data/literature.json
npm run dev -- --port 5199 --host 127.0.0.1
npm run build                       # → dist/，静态托管
npm run lint                        # oxlint
```

## Problems

- **TS 编译 6 处报错**：`locale={{}}` 需传 `zhCN`；`AreaOutlined` 改名；`StackedColumn` 改 `Column`+`stack`；一个未使用的 `j` 参数；一个未使用的 `expanded` state 改为受控 `expandedKeys`。逐项按 CLI 查到的 API 修正。
- **`npm run lint` 偶发一次 `ESLint output (JSON parse failed)` 且 exit=1**：直接跑 `oxlint` 与连跑 5 次 `npm run lint` 均干净（0 diagnostics / 10 files），判定为抖动而非配置问题，未改配置。
- **首屏 2.4 MB chunk 警告**：根源是 G2 被打进图表页。改为按页签 `React.lazy` 后首屏约 300 KB，图表页 1.4 MB 延后加载，再调阈值消除噪音。

## Verification

- `tsc -b` 通过；`oxlint` 0 diagnostics；`npm run build` 无警告（544 ms）。
- `python3 scripts/prepare_data.py` 重构前后输出 MD5 一致（`8c62d2a3…`），确认路径重构未改变数据。
- headless Chrome 截图核验：Methods 页排除记录表 7 行全部渲染；Dashboard 页 8 张图全部正常。
- `vite preview` 起服务验证 `index.html`、`/data/literature.json`（1,952,020 B）、`#tab=library` 深链均 HTTP 200。

## Result

四页签站点可用：趋势总览 / 文献库（1709 条可筛可导出）/ 期刊指标（179 种）/ 方法与口径。
数据与 literature.xlsx、trend_report.pptx 同源。dev server 运行于 `http://127.0.0.1:5200/`（原请求 5199 被占用，Vite 自动改端口）。
