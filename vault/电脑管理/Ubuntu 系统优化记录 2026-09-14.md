## 1. 磁盘与分区重构

### 1.1 调整前面临的问题

- `/home`（nvme0n1p7）只有 **64G，已用 91%**，仅剩 5.8G
- p3（140G，`home-new`）是旧 home 副本；p10（100G，`backup`）几乎为空
- p4 Data 分区（438G NTFS）残留 Windows 时代垃圾

### 1.2 /home 迁移：p7 → p3（140G）

流程（全程可回滚）：

```bash
# 1. 增量同步（不删目标文件，保护数据）
rsync -aHAX --one-file-system --exclude='lost+found/' /home/rlcao/ /mnt/newhome/rlcao/

# 2. 修改 fstab（UUID 换成 p3）
# /dev/disk/by-uuid/667ffcd0-... /home ext4 defaults 0 1

# 3. 重启验证
```

- 迁移后 `/home` 从 64G → **137G**，已用 42%
- 旧 p7 完整保留作为回滚（后来被复用，见下）

### 1.3 p7 + p10 合并为 Btrfs 卷（165G）

由于两个分区物理不相邻（中间隔着 p8、p9），无法常规合并，改用 **Btrfs 多设备卷**：

```bash
mkfs.btrfs -f -L BTRFS-DATA -d single -m dup /dev/nvme0n1p7 /dev/nvme0n1p10
# fstab: UUID=3201e632-... /mnt/data btrfs defaults,noatime,compress=zstd:3,nofail,x-gvfs-show 0 0
```

| 参数 | 含义 |
|------|------|
| `-d single` | 数据单份，两分区容量合并可用 |
| `-m dup` | 元数据双份（同盘双分区），可自修复 |
| `compress=zstd:3` | 自动压缩（实验数据/文档收益大） |

挂载点 `/mnt/data`，当前 5.8M 已用，163G 可用。

## 2. 系统问题排查与修复

### 2.1 开机慢 1min41s —— 已修复

**原因**：fstab 里失效的 `/mnt/win` 条目（设备早已不存在），开机等待设备超时 90 秒。

**修复**：删除该条目 + 清理空目录，开机回到 ~10 秒。

### 2.2 Termius AppArmor 日志刷屏 —— 已修复

**根因**：`/etc/apparmor.d/termius-app` 是 **complain 模式**（只记录不拦截），每次文件访问都写一条 audit 日志，22 分钟 2600+ 条，是 `/var/log` 膨胀到 1.2G 的主因之一。

**修复**：

```bash
ln -sf /etc/apparmor.d/termius-app /etc/apparmor.d/disable/termius-app
apparmor_parser -R /etc/apparmor.d/termius-app
```

### 2.3 崩溃转储与日志膨胀清理

| 项目 | 处理 |
|------|------|
| `/var/crash` 381M（13 个应用崩溃转储） | 已删除；apport 已关闭（不再产生） |
| `syslog.1` 381M + `kern.log.1` 135M | 已清理 |
| journal 413M | `journalctl --vacuum-size=200M` → 187M |

### 2.4 包与内核清理

- **rc 残留包 41 个**（feishu、codebuddy-cn、rstudio、npm、v2rayn、winbind、ncbi 等配置残留）→ 已 purge

## 7. 经验记录

1. **VS Code profile 不继承默认配置**——所有设置要分别写入各 profile
2. **`pipefail` + `grep -q` 陷阱**：`systemctl list-unit-files | grep -q` 会因 SIGPIPE 误判，改用 `systemctl cat`
3. **Ubuntu 的 NTFS 默认走 ntfs-3g（FUSE）**，即使内核有 ntfs3；fstab 写 `auto` 时优先匹配已安装的 ntfs-3g
4. **ath11k 网卡的 "invalid MCS" 警告**会在内核日志产生大段栈回溯，属驱动噪音
5. **apport 崩溃转储很占空间**（曾达 381M），不开发调试可关闭
6. Btrfs 多设备卷可把不相邻分区合并（`-d single -m dup`，同盘无需 RAID1）
