# 《应用技术》案例题 · 答题模板

>这是**真正决定过不过的一科**：两科须同次双过 45 分，案例靠"写得出、写全、写对术语"给分。
>官方命题范围见 [[考试概览]] 第四节 —— **第 3–16、19、20 章**，第 1、2 章不出案例。

## 一、通用结构（对着抄）

任何案例题，答题骨架固定为：

```
1. 定性：这是什么问题 / 属于哪个管理过程（挂标准术语）
2. 依据：引用框架或标准（ITIL、ITSS、等保2.0、SLA、PDCA…）
3. 分条措施：每条形如「角色 + 动作 + 输入/输出 + 指标」
4. 收口：评估与持续改进（复盘、度量、文档化）
```

**给分规律（机构经验）**：按点给分 → **宁多分条，不写大段散文**；术语写全称 + 缩写；涉及服务就带 **SLA / RTO / RPO** 等指标。

## 二、三类高频题型专项

### 类型 1 · 故障排查（最高频）

**固定四步**（希赛明确点名，缺步就扣分）：

>**定位问题 → 分析日志 → 隔离环境 → 验证修复**

补强写法：再补"**复盘与预防**"（根因分析、知识库沉淀、监控告警优化）——多写一步通常多得一步分。

### 类型 2 · 方案设计（运维/服务管理方向）

- 起手挂标准：**ITSS**（信息技术服务标准）、**ITIL**、**SLA**
- 主体用过程名分条：服务级别管理 / 服务报告 / 事件 / 问题 / 配置 / 变更 / 发布 / 可用性与连续性 / 容量 / 运维安全
- 每条落到「**谁做 + 做什么 + 交付什么文档 + 考核什么指标**」

### 类型 3 · 数据库设计 / E-R

- 按"**实体 → 属性 → 联系（1:1 / 1:n / m:n）**"顺序答
- 联系若为 m:n，必须写出**中间表**及主键
- 补一句"符合第三范式（3NF），必要时反规范化以提升查询性能"
- SQL 部分：JOIN / GROUP BY 写规范，注意条件与别名

## 三、必写术语本（背下来，答题时往上挂）

| 领域 | 术语 |
|---|---|
| 服务管理 | ITIL（事件/问题/变更/配置/发布管理）、ITSM、服务台、SLA、OLA |
| 服务标准 | ITSS、ISO/IEC 20000 |
| 安全 | 等保 2.0（分级—定级—备案—建设整改—测评—监督检查）、CIA 三要素、零信任、最小权限 |
| 容灾恢复 | **RTO（恢复时间目标）、RPO（恢复点目标）**、同城/异地灾备、备份策略 3-2-1 |
| 数据治理 | DCMM、DAMA、元数据、数据质量、数据分类分级、数据脱敏 |
| 项目管理 | WBS、EVM（挣值：PV/EV/AC、CV/SV/CPI/SPI）、变更控制、干系人 |
| 运维改进 | PDCA、配置管理数据库 CMDB |
| 架构 | TOGAF（如教程涉及）、架构分层、云原生 |

## 四、常见失分点（照着自查）

- ❌ 只写"加强管理""提高意识"这类空话 → ✅ 换成"由**服务台**登记事件，**二级支持**在 SLA 约定时限内响应"
- ❌ 故障题漏掉"隔离环境" → 直接扣步骤分
- ❌ 方案题不提标准 → 显得不专业，丢术语分
- ❌ 通篇散文不分条 → 阅卷找不到点
- ❌ 漏 RTO/RPO → 容灾题几乎必写
- ❌ 时间分配失衡 → 选择题控制在 **≤60 分钟**，案例留足 90 分钟以上

## 五、练习方法

1. 先看题干，**限时手写**（机考就是打字，练键盘输出）；
2. 写完对照参考答案，**用红笔标出漏掉的术语与步骤**；
3. 把漏掉的补进本页"术语本"；
4. 用 [[知识体系]] 对应章节回炉该考点。

>判断标准不是"我懂了"，而是"**我能在 15 分钟内、不看资料，写出结构化的一页纸**"。
